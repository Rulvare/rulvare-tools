How it works

This tool is for game developers and technical artists who need a quick estimate of texture memory while planning a budget for mobile, console or PC.

Uncompressed formats store a fixed number of bytes per pixel: bytes = width × height × bytesPerPixel.

Block-compressed formats (BC1–BC7, ETC, ASTC) store fixed-size blocks: bytes = ceil(width / blockW) × ceil(height / blockH) × blockBytes. A 1×1 or 2×2 mip still takes a whole block, so small mips cost slightly more than "bpp × pixels".

Mipmaps: level i is max(1, floor(width / 2i)) × max(1, floor(height / 2i)), down to 1×1. There are floor(log2(max(width, height))) + 1 levels. A full chain adds about 33% to the base level.

Total = (sum of all mip levels) × faces or layers (cubemap = 6) × number of textures × 2 if a CPU copy is kept.

Notes and limits

  • This is an estimate of the raw texel data. Drivers may add padding, alignment or tiling, and an engine's profiler can report slightly different numbers.
  • RGB24 is shown as 3 bytes per pixel, but many GPUs store it as 4 bytes (RGBA32). Check your engine's profiler for the real value.
  • Crunch, Basis/KTX2 supercompression and file compression reduce the download or disk size, not GPU memory. Once loaded, the texture uses the size of its GPU format (for example BC7 or ASTC).
  • ETC1 and BC1 do not store alpha (BC1 has 1-bit alpha). Not every format is supported on every platform: BC is typical on desktop and consoles, ASTC and ETC2 on mobile.
  • 1 MiB = 1,048,576 bytes. Sizes are shown in KiB/MiB/GiB (binary units), which is what most engine profilers use.
